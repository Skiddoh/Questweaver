# Questweaver

Questweaver is a standalone, cooperative RP addon for WoW Forever. It stores custom-item and quest data locally; it uses WoW addon whispers only to exchange bounded, escaped data. It deliberately does not try to be a cheat-proof economy.

## Install

1. Copy this `Questweaver` directory into `World of Warcraft\Interface\AddOns\Questweaver`.
2. Ensure `Questweaver.toc` and the eight `.lua` files sit directly in that folder.
3. Enable **Questweaver** at character select, then log in and run `/qw`. The manifest supports WoW Forever interface `16000` and `16001` in `_classic_beta_`.
4. Both players need the same addon version/protocol and must be able to receive addon whispers.

The draggable bag icon on the right edge of the screen, or `/qw inventory` (also `/qw inv`), opens the **RP Satchel** directly. The nearby quest-note icon (or `/qw active`) opens only accepted, in-progress RP quests. Active objectives are also shown in a collapsible **Questweaver** section just beneath the Blizzard objective tracker; click the heading to collapse/expand it and click the quest-note icon for full details and actions. Since these are custom addon quest IDs rather than Blizzard server quests, they are displayed in this companion tracker rather than inserted into Blizzard's server-backed Quest Log. The high-layer `NPC` gossip button below them runs **NPC interaction**: target a Questweaver quest giver and left-click it, exactly like `/qw interact`. Shift + left-drag any of the three icons to move it. The satchel is a separate 32-slot visual inventory; it never changes the normal WoW backpack.

## MVP workflow

The `/qw interact` window stays bound to its selected NPC and closes if the player changes target or moves outside the client's NPC interaction-distance check. The addon polls the client proximity API out of combat and does not use map coordinates; if the client withholds that API during combat, it leaves the window open until the check is available again.

The on-screen satchel shortcut uses the blue leather bag icon. A separate coin shortcut displays your current RP Token balance, updates as tokens are awarded, removed, or traded, and opens the RP inventory when clicked. Shift + left-drag moves it; its position is saved.

The **Create** tab is a launcher for dedicated **Create RP item** and **Create and share quest** windows. The item window has a large live icon preview and a **Browse icons** palette. It loads the client's macro-icon library when available and always includes common book, coin, letter, note, key, map, and gem textures. You may still paste any valid icon path. The **RP Satchel** tab renders owned item icons in a backpack-style grid; hover an icon for its description and quantity, or click it to select it for a trade or removal. Enter a whole quantity and click **Remove selected** twice to confirm. This only removes items from the separate RP Satchel; the Maker definition and normal WoW backpack are untouched.

The **Sets** tab (also `/qw sets`) organizes authored RP content into a **Questweaver Set**: a named story with an ordered chapter list of quests and supporting RP items. Use **Create Questweaver Set** from Create, choose chapters/items from the browser, and save it. Sets only reference stable IDs; they do not duplicate the underlying quests or items, so you can edit their story order safely. Use the set editor's **Choose quest chapters** and **Choose supporting items** buttons instead of copying IDs. In the quest editor, right-click an Item ID or Quest ID field to open the same browser.

Use `/qw trade` (or **Open RP trade window**) for trading. It presents an in-game-trade-style panel with your offer on the left, the other player's offer on the right, a clickable row of your RP inventory, quantity selection, and clear confirmation state. Select an item, enter the recipient name, and choose **Offer / update**. Both players choose **Confirm** for the same trade. Updating an offer resets both confirmations. The proposer deducts only after the receiver has persisted the transfer and acknowledged it. A committed trade remains visible and may be resent after a disconnect; it is never silently discarded.

The quest editor separates General details from Objectives. In Objectives, **Add objective** opens a type list; choose one, fill its fields, then click **Add to objective list**. The ordered objective list scrolls and supports up to 12 objectives. Set **Step number** to control dependencies: all objectives with the same number are active together; a higher number unlocks only after every objective in the current lower-numbered group is complete. Numbers may be skipped and objectives can be rearranged by editing their number. Older quests default to one objective per step in their existing order. Click a row to edit it, use **Update objective** to save edits, or click its **X** to remove it. Supported types are `kill`, `collect`, `loot`, `dialogue`, `deliver`, `possess`, `visit`, and `manual`. The generated sequence uses `type~itemId~count~placeId~mobName~text~stepNumber`; normal creation does not require editing it. Define actual in-game locations separately as `placeId~zone~x~y~radius~description` entries. `zone` must exactly match the recipient's client zone name; coordinates are map percentages (0–100), with a radius in map-percentage units. Leave all three coordinate fields empty for a zone-only objective, for example `oldtown~Stormwind City~~~~Meet in Old Town`; or require a position with `librarian~Stormwind City~52~64~3~At the library`. A step's `placeId` must point to one.

Every assigned objective checks the current zone. If the location has coordinates, it also uses the WoW world-map position API and only progresses within the configured radius. The quest share bundles the reward, every item referenced by a step, and any **Additional quest item IDs** as validated item definitions—recipients receive definitions but not the items themselves.

Rewards are immediate by default. To require a return, set **Reward turn-in NPC ID** in the quest creator. Choose **Use giver** to use the configured quest giver, or enter a different `npc:ID`. After the final objective the quest becomes **ready to turn in**; target that NPC and use the gossip icon or `/qw interact` to receive the reward. The Aldrassil boar demo now requires reporting back to Conservator Ilthalaine (`2079`).

`collect` is the position-only item pickup objective. Since there is no in-game object to click, it grants the configured RP item when the recipient reaches the configured place and presses **Collect item here** in the journal. `dialogue` can require both a configured place and a targeted NPC; target that NPC in-game and use **Use targeted NPC** while authoring. The player then targets that same NPC and uses `/qw interact` (or the **Talk / interact with NPC** journal button); the step advances only at its configured place when one is specified. `deliver` uses the same optional NPC/location validation before it sends an RP item to the quest owner. `visit` records a real zone/location visit when advanced. `possess` checks that the configured RP item is in the RP Satchel.

`kill` is automatic and identity based. Use `kill~~5~~npc:1984~Defeat five boars` to require five player killing blows on NPC template ID 1984; the counter updates from the combat log and completes the step automatically wherever that NPC is killed, regardless of client language or zone. Each counted kill prints `Kills: current / required` in the chat box, and completed objectives print their completion and reward/follow-up result there too. Kill objectives ignore location fields; use `visit`, `collect`, or another location-aware objective when a quest step must happen in a particular place. Older name-based kill quests continue to work, but their target name must match the recipient's client language exactly.

To create an NPC-targeted objective without looking up or typing an ID, target the creature in-game, open **Create quest**, select `kill`, `dialogue`, or `deliver`, enter the relevant text/fields, then click **Use targeted NPC** and **Add objective**. `kill` requires an NPC ID; dialogue and delivery can use one when the step should happen with a particular NPC.

Quests can be linked into a linear follow-up chain. Create and note the quest ID of the other quest, then use either optional link field in the creator: create the later quest first and enter its ID as **Follow-up quest ID** on the earlier quest; or create the earlier quest first and enter its ID as **Predecessor quest ID** while creating the later quest. The predecessor route writes the earlier quest's follow-up link automatically. When you share the first quest, Questweaver transfers up to six linked definitions to the recipient as deferred follow-ups. Completing a quest activates its next quest automatically; it is not visible as active beforehand. If a deferred definition is missing after a disconnect, the completed quest stays complete and shows an explicit request to have its owner share the chain again.

To make an NPC give a custom RP quest, define the NPC's real template ID by targeting it and choosing **Use NPC** in the quest creator. Add its optional configured place ID and the text it should say in **Quest giver dialogue**, then create the quest and choose **Send NPC offer** instead of **Share active**. The recipient sees an **NPC OFFER** in the Quest Journal, targets that NPC at the configured location, reads the dialogue, and chooses **Talk / accept quest**. The quest becomes active only then. This is Questweaver's own dialogue panel; it does not alter Blizzard/Forever NPC gossip or server quests.

The quest editor is split into **General** and **Objectives** sections. General contains quest identity, reward, locations, suggested level/player count, NPC settings, repeatability, and sharing details. Objectives contains the ordered objective builder and sequence editor. Use **NPC conversations** on Create or `/qw conversation` to open a dedicated editor: target/select an NPC ID, write its dialogue, and choose up to 12 authored quests for its offer list. The local target gets a **CUSTOM DIALOGUE** entry and listed quests under **NEW QUESTS**. **Save + share** sends those quest definitions as explicit NPC offers to one player; that player must target the configured NPC and accept each quest. Suggested level (1–999) and player count (1–40) are optional hints only; they never gate quest acceptance or progress. The **Repeatable** toggle defaults to **No** and enables an NPC to offer the quest again after completion. The Quest Journal groups authored definitions under **Your Quests**, finished runs under **Completed**, and accepted/offered quests under **Open Quests**. Selecting one of your quest definitions shows **Edit quest** and **Share quest**. Authored definitions are managed separately from the RP Satchel: use the **Maker** tab or `/qw maker` to inspect definitions and grant eligible items to your satchel. Creating an item defines it only; it does not create player-owned quantity. Quest items and rewards are granted only through quest actions. Other categories (`misc`, `weapon`, `armor`, `food`) can be added from Maker inventory, up to their max-stack amount. Deleting a quest, set, or item definition requires confirmation and refuses unsafe deletions with active/referenced data.

`/qw npcid` prints the selected creature's name and NPC template ID in the chat box. It uses WoW Forever's creature-ID API when present, with modern and raw-1.12 GUID fallbacks. Use it before authoring an NPC objective or reward turn-in. `/qw interact` is the faster in-world version: target a configured quest giver, then run the command to read/accept the first matching Questweaver offer. Conservator Ilthalaine (NPC `2079`) is configured as the giver for the built-in Aldrassil Boar Hunt. Target him in Shadowglen and run `/qw interact` to create and accept the demo automatically; it will not duplicate an already accepted or completed demo quest.

If kill progress does not appear, `/qw killdebug on` prints an immediate confirmation and reports whether the structured `PARTY_KILL` and combat-log events are available on this client. Unsupported combat-chat events are not registered. Use `/qw killdebug off` to disable diagnostics.

Every Questweaver installation includes the `item:questweaver:rp-token` item definition. It is not placed into the RP Satchel for free; it is available as a standard quest reward. The **Create Aldrassil boar demo** button creates an idempotent quest for five NPC `1984` Young Thistle Boars, rewarding one RP Token. Kills count wherever that NPC is killed. Both demo buttons also assign their quest to the current character immediately, so it appears in the active-quest view; clicking again preserves existing progress.

Use `/qw` and select **Quests** (or use `/qw quest`) to open the journal. **ACTIVE** entries are quests received from another player: select one and use **Progress objective**. **YOUR QUEST** entries are definitions you authored: select one, enter the target character in **Share with**, then click **Share quest**. **Open editor** remains available for changing the quest definition.

Use **Remove accepted quests**, then click it again to confirm, to clear only the current character's accepted quest records. Authored quest definitions remain available for sharing. The action is blocked while any quest has an unacknowledged delivery, so that delivery can be resent or resolved first.

Delivery removes the item only after creating a persisted pending delivery, and the owner adds it exactly once before acknowledging. Manual objectives send an approval request; the owner sees an explicit **Approve with: quest ID | step | player** line in Recent Requests and the approval field is prefilled. Rewards are added once on completion.

The **Create sealed-letter demo** makes a Sealed Letter and a four-step quest. Player A trades the Sealed Letter to player B, shares the quest, then B completes dialogue/possession and delivery. The delivery returns the letter to A's RP inventory. A manually approves; B receives the standard RP Token.

## Safety and limits

Saved data has a version, player-generated stable IDs, and persisted processed-transfer/delivery IDs. Incoming data is never evaluated as Lua: it is decoded as escaped fields, schema/length checked, and bounded to 24 chunks/4 KB. Chunks are queued at one each 0.35 seconds and abandoned after 90 seconds. Replayed commits/deliveries are idempotent. Offers carry a revision; receiving a replacement offer clears both confirmations. Cancellation applies only before commit; post-commit interruptions remain explicit `committed`/`unresolved` records so players can resend or resolve them collaboratively.

This is cooperative RP software. A player can alter SavedVariables or refuse to acknowledge a message; it cannot prevent that.

## Tests and client validation

Offline tests are in `tests/core_logic.lua` and can run with Lua 5.1+ (`lua tests/core_logic.lua`). They exercise escaping, validation, inventory, punctuation-safe item serialisation, idempotent transfer/delivery acknowledgement, places, target-validated quest loot, and automatic kill counters using WoW API stubs.

Still requires the Forever client: verifying the exact current addon-message argument order/channel behavior, icon rendering, UI templates, whisper delivery across realm naming, world-map coordinate behavior, and real logout/disconnect recovery. Use the two-player checklist in `TEST_CHECKLIST.md` before RP use.

In the current NPC interaction flow, `/qw interact` and the NPC icon open a separate window instead of immediately accepting/completing anything. The window has expandable **New quests**, **Active quests** (including ready reward turn-ins), **Completed quests**, **Repeat quests**, and **Custom dialogue** sections. Completed and repeat sections start collapsed. Select an entry to read it and use its action button; **Accept again** is only offered for quests whose owner enabled **Repeatable** in the editor. Completion history is retained in SavedVariables. NPC interactions use the selected NPC ID and rely on the game for proximity; they never require map coordinates. The Ilthalaine demo is offered in the window and must be explicitly accepted.

For item chat links, right-click an RP item in the Inventory tab while a chat edit box is open; this inserts only safe plain text in the form `[Item Name]`. Use `/qw link <item ID>` to print that name locally. Questweaver chat filters turn matching names into a local icon and clickable preview for addon users who already have that item definition; players without the addon see only the item name. No custom hyperlink escape is sent to player chat, and mentioning an item never grants it.
